RUN 1 (engine B transition) -- 29 passed / 1 failed
----------------------------------------------------
Identical parts 1 and 2, except engine B read "HTTP -1" (DNS gone) and engine C
read "HTTP -1" as well; both classified OFF.

The one failure was a REAL BUG in the first version of the classifier, found by
this proof and then fixed:

  PASS  shutdown confirmed on the real engine  [off -- confirmed terminated (/api/ps now 502 after 2 checks)]
  FAIL  after a confirmed shutdown it reads OFF  [waking - kernel running, engine not answering yet]

Cause: after the shutdown was confirmed at the engine, Kaggle's own kernel status
still read "running", and the classifier trusted it, so the card flipped from OFF
back to WAKING on the next poll. Fix: a shutdown measured at the engine
(/api/ps watched stopping) outranks Kaggle's lagging control-plane field, and is
dropped the instant the engine answers 200 again. Run 2 above proves the fix on a
second engine, including the counter-cases (a revived engine still reads LIVE; a
new wake is not shadowed by the record).

Real transition observed on engine B in run 1:
  before: OFF -> push accepted (versionNumber 8) -> WAKING (kernel running)
  -> LIVE at "9 min left" (real /api/ps 200 with IQ4_XS loaded)
  -> shutdown confirmed (/api/ps 502 after 2 checks)
